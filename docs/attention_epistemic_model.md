# RC20 语义注意力判断 Skill 模型

## 0. 纠偏说明

本文件不再把 `Observation → Interpretation → Belief → Policy` 设计成插件程序中的运行流水线。

该方向会把插件变成第二个判断主体，与本项目的真实分工相冲突：

- **程序便宜、快、确定，但高语境判断弱。**
- **主对话 AI 昂贵、慢、概率性强，但高语境判断强。**
- **Skill 文档负责把可复用的判断依据、词关系、反例和工具边界交给主对话 AI。**

因此，rc20 的目标不是新增“认识引擎”，而是把认识论写进 AI 可理解、可联想、可迁移的语义基础设施。

插件程序仍然只是能力器官和确定性执行层，不替主对话 AI 判断“谁在刷屏”“什么与任务相关”“是否值得回响”。

---

## 1. 正确的职责分配

| 层 | 优势 | 应承担 | 不应承担 |
|---|---|---|---|
| 主对话 AI | 语境理解、词关系联想、跨消息归因、目的判断 | 判断意义、相关性、风险、价值、是否调用工具 | 把未验证执行结果说成事实 |
| Skill 文档 | 低成本复用语义结构，可随模型加载 | 提供概念边界、关系词、反例、最小副作用原则、工具使用语义 | 写成封闭状态机或关键词触发器 |
| 插件 Runtime | 快、便宜、确定、可审计 | 精确对象 ID、时间、计数、租约、权限、存储、调度、前置门、真实回执 | 语义分类、意图推断、自动判断骚扰或相关性 |

可以把责任边界概括为：

```text
主对话 AI：理解“为什么、是否、为了什么”
Skill：提供“哪些关系值得联想、哪些概念不能混同”
插件程序：执行“对谁、多久、多少次、允许还是拒绝”
```

这只是职责边界，不是要求 AI 按固定程序图逐节点运行。

## 2. 机制与效果必须分离

很多看起来像“新功能”的东西，只是已有机制在不同语境中的组合效果。

### 2.1 底层机制

rc19 已经提供或接近提供的机制包括：

- 精确对象作用域；
- 对象、时间、计数三个可组合句柄；
- `activate / ignore` 两种竞争效果；
- 有限租约与到期恢复；
- 权限控制；
- 前置低成本过滤；
- 工具调用与真实回执；
- 非递归、有限次数的主动再激活。

### 2.2 表面效果

以下效果不应各自演化成独立“智能模块”：

| 表面效果 | 机制组合 |
|---|---|
| 追踪某人 | 对象 + 有限时间 + Activate |
| 心跳 | 时间 + Activate |
| 条件激活 | 对象/时间/计数句柄组合 + Activate |
| 防刷屏 | 对象 + 时间窗口 + 计数 + Ignore |
| 临时压制追踪对象 | 原 Activate 租约不删除，叠加更短 Ignore |
| 回响 | AI 显式授权 + 时间句柄 + 有限次数 Activate + 禁递归 |
| 沉默 | Agent 已判断，但没有公开输出；控制工具仍可调用 |

如果一种新需求可以由现有机制组合得到，就优先改 Skill 的语义说明和工具选择示例，而不是新增程序分支。

## 3. Skill 应写“词关系网”，而不是程序判断图

LLM 的优势不是执行固定流程，而是根据上下文中的词、对象、状态、方向和目的形成关系联想。

因此 Skill 的基本单元不应是：

```text
if 消息数 > 5:
    ignore()
```

而应是可以迁移到不同语境的关系描述：

```text
高频 ≠ 必然恶意
重复 + 无任务增量 + 持续触发成本 → 更接近对抗性噪声
连续补充 + 同一未完成任务 + 信息增量 → 更接近正常任务延续
```

### 3.1 实体词

Skill 应让 AI 关注这些实体及其关系，而不是只匹配关键词：

- 主对话 AI；
- 管理员 / 操作员；
- 发言对象；
- 被追踪对象；
- 群聊 / UMO；
- 当前任务；
- 触发事件；
- 激活租约；
- 忽略策略；
- Echo Hook；
- 工具回执。

### 3.2 状态词

- 已激活 / 未激活；
- 已追踪 / 未追踪；
- 被临时忽略 / 忽略到期；
- 待执行 / 已取消 / 已跨过执行边界；
- 有新事实 / 无新事实；
- 相关 / 无关 / 不确定；
- 有公开价值 / 只有控制面价值。

### 3.3 关系词

- 触发；
- 覆盖；
- 叠加；
- 暂时压制；
- 到期恢复；
- 取消未来；
- 无法追回过去；
- 延续；
- 补充；
- 打断；
- 重复；
- 关联；
- 冲突；
- 放大成本；
- 降低成本。

### 3.4 方向词

- 扩大 / 收缩注意力入口；
- 增加 / 减少资源消耗；
- 延长 / 缩短有效期；
- 增强 / 减弱证据；
- 从不确定走向可行动；
- 从在途走向不可撤回。

### 3.5 概念对照

这些对照应长期保存在 Skill 中，作为语义锚点：

- 激活 ≠ 回复；
- 忽略 ≠ 永久删除；
- 沉默 ≠ 什么都不做；
- 回响 ≠ 长期追踪；
- 回响次数 > 1 ≠ 递归；
- 监听 ≠ 激活；
- Cron ≠ 主动权限来源；
- 模型能力 ≠ 插件权限；
- 高频 ≠ 必然骚扰；
- 工具调用成功 ≠ 目标效果已经被外部世界验证；
- 取消未来 ≠ 追回已开始执行。

## 4. 四个核心语义关系簇

### 4.1 激活关系簇

可能支持激活的语境关系：

- 当前消息与 AI 自身职责相关；
- 与正在进行的任务存在延续或关键补充；
- 来自被明确授权关注的对象；
- 时间或计数条件已经满足管理员授予的激活范围；
- 不介入会遗漏明确承诺或必要动作。

反例：

- 被激活不代表必须发言；
- 仅仅“有人说话”不构成主动介入理由；
- 仅仅模型能力较强不构成主动权限。

### 4.2 忽略关系簇

可能支持有限 Ignore 的语境关系：

- 同一对象重复制造激活但没有信息增量；
- 行为持续放大 Token / 工具成本；
- 与当前任务无关，且明显打断已建立职责；
- 已经出现对抗性利用 @、引用或追踪机制的迹象；
- 需要临时减少注意力，但不应销毁原追踪意图。

反例：

- 高频但每条都在补充关键信息；
- 紧急故障排查中的连续状态更新；
- 多个用户分别提供证据；
- 仅凭不喜欢某种表达方式就长期忽略对象。

### 4.3 回响关系簇

可能支持 Echo 的语境关系：

- 当前真实激活揭示了一个尚未完成的上下文；
- 用户或群成员很可能稍后补充；
- 当前不需要持续追踪，只需要有限地再检查一次；
- 再检查的目标可以用自然语言明确说明；
- 没有相关新事实时，AI 应沉默。

反例：

- 普通闲聊结束后自动续命；
- Echo 回合再创建 Echo；
- 用大量预排次数伪装长期监听；
- 已有新的真实激活后仍保留旧 Echo 重复唤醒。

### 4.4 沉默关系簇

可能支持 Yield 的语境关系：

- 本轮已经得到注意机会，但没有公开回复价值；
- 已完成必要的控制面动作；
- 发言只会重复、打断、暴露内部治理或制造噪声；
- Echo 检查没有发现相关新事实。

反例：

- 把“沉默”误解成不能调用 Ignore / Cancel 等控制工具；
- 先发出公开内容，再尝试用 Yield 撤回；
- 用可见的“我保持沉默”代替真正无输出。

## 5. 程序应保持弱判断

### 5.1 程序允许做

- 精确匹配对象 ID；
- 维护计数器和滑动时间窗口；
- 判断租约是否到期；
- 检查配置权限；
- 执行前置 Gate；
- 持久化策略意图；
- 调度一次性或周期任务；
- 返回成功、失败、部分成功、结果不确定；
- 在明确策略已经存在时快速过滤后续事件。

### 5.2 程序禁止做

- 根据词频自动断言“这是骚扰”；
- 根据模型名称自动提升权限；
- 自动创建对象 Ignore；
- 自动判断某条消息与任务相关；
- 把全局消息都送进一个程序分类器再决定公平性；
- 用硬编码关键词替代 AI 的语境判断；
- 把“功能名称”继续膨胀成新的并行状态机。

程序的判断只能建立在已经由管理员配置或 AI 显式工具调用形成的确定性状态上。

## 6. 认识论兜底不等于程序化认识层

认识论应成为 AI 判断时的语言约束，而不是新建数据库和状态流水线。

Skill 应要求 AI 在高语境判断中保持这些区分：

### 6.1 事实与解释

- “10 秒内收到 8 次可激活事件”是事实；
- “对方在恶意刷屏”是解释。

解释可以支持动作，但不能冒充事实。

### 6.2 证据与结论

AI 应寻找支持和反驳同一解释的语境关系，例如：

- 是否有信息增量；
- 是否围绕同一任务；
- 是否来自同一对象；
- 是否造成重复激活；
- 是否存在紧急性；
- 是否有人明确要求继续关注。

### 6.3 当前判断与长期身份

一次噪声行为只能支持有限策略，不能直接把对象永久身份化为“垃圾用户”。

### 6.4 执行事实与未来承诺

只有工具回执明确成功，才能说策略已经建立；只有后续检查真的发生，才能说已经回响。建议恢复、可能重试、已经安排重试三者不能混淆。

### 6.5 最小副作用

多个工具都可达时，优先选择：

- 作用域更小；
- 时间更短；
- 可撤销；
- 不影响其他对象；
- 不停止无关插件；
- 不扩大主动权限。

## 7. 借鉴对象：借机制，不照搬程序图

### 7.1 ReAct

ReAct 的可借鉴点是：语言模型负责结合语境进行推理并选择外部动作，动作结果再成为后续判断依据。这里借的是“AI 判断 + 外部工具执行”的职责分离，不要求插件复制显式 Thought/Action 状态机。

参考：Yao et al., *ReAct: Synergizing Reasoning and Acting in Language Models*, arXiv:2210.03629。

### 7.2 Toolformer

Toolformer 的可借鉴点是：是否调用 API、调用哪个 API、使用什么参数，本质上属于语言模型的决策问题；工具本身提供便宜、确定的专门能力。

参考：Schick et al., *Toolformer: Language Models Can Teach Themselves to Use Tools*, arXiv:2302.04761。

### 7.3 Semantic Kernel Plugins

Semantic Kernel 强调，只有函数接口还不够；输入、输出和副作用必须用 AI 能理解的语义描述清楚，模型才能正确选择工具。该原则与本项目的 Skill / Tool 语义层高度一致。

参考：Microsoft Semantic Kernel 官方文档，*Plugins in Semantic Kernel*。

这些项目共同支持的不是“把判断写成程序图”，而是：

> 让模型掌握语义化工具说明和任务上下文，让程序负责可靠执行。

## 8. 验证方法也必须分层

### 8.1 Runtime 确定性验证

继续验证：

- 精确对象隔离；
- 时间 / 计数边界；
- 租约到期；
- Echo 禁递归；
- 取消真值；
- 权限与配置；
- 存储失败策略；
- AstrBot 宿主兼容。

这些测试不需要 AI。

### 8.2 Skill 语义验证

Skill 的质量不能通过程序单测证明，应使用高语境最小对照组：

- 同样 10 秒 5 条消息：一组是无增量刷屏，一组是紧急故障补充；
- 同样是被追踪对象：一组需要临时 Ignore，一组需要继续关注；
- 同样是未完成话题：一组需要一次 Echo，一组只是普通闲聊结束；
- 同样没有公开回复价值：一组需要先做控制工具，一组直接 Yield；
- 同样出现工具错误：一组是接口失败，一组是权限未开，一组是回执不确定。

评价指标不只是“调用了哪个工具”，还包括：

- 是否避免不必要工具；
- 是否选取最小副作用参数；
- 是否区分事实与解释；
- 是否在权限关闭时停止提权；
- 是否根据工具回执更新结论；
- 是否在反例变化后改变选择。

语义评测应跨多个模型、多个措辞和顺序扰动运行；单一模型一次 PASS 不能证明 Skill 理论正确。

### 8.3 失败归因

以后统一区分：

1. **接口失败**：工具、AstrBot、API、Schema 不可达；
2. **执行状态失败**：程序没有正确保存、触发、取消或恢复；
3. **Skill 语义失败**：文档概念含混、关系缺失、反例不足；
4. **模型判断失败**：在明确 Skill 下仍误解语境或错选工具；
5. **机制失败**：现有对象/时间/计数/效果/租约原语无法表达真实需求；
6. **理论失败**：机制与语义模型整体不能解释反例。

只有第 5、6 类失败，才优先考虑增加或重构机制。前四类不应通过堆新功能掩盖。

## 9. rc20 的最小工作范围

rc20 当前只做：

1. 审计现有 `SKILL.md` 是否仍含程序化、关键词化判断；
2. 把判断依据改写为关系词、概念对照、语境簇和反例；
3. 审计七个工具的名称、参数、返回值和副作用描述是否足以让 AI 正确联想；
4. 建立语义最小对照评测；
5. 根据失败归因决定是否真的缺少底层机制。

当前明确不做：

- Observation Engine；
- Interpretation Engine；
- Belief Database；
- 程序自动语义分类；
- 全量监听；
- 新增更多表面功能；
- 为每种效果建立独立状态机。

---

## 10. rc20 成功标准

rc20 的成功不以“新增多少功能”为标准，而以以下结果为标准：

- Runtime 代码几乎不增加，主 AI 的工具选择却更准确；
- 同一机制能解释和组合更多效果；
- Skill 能处理反例，而不是依赖关键词命中；
- 高语境判断留在主对话 AI；
- 程序继续保持快、便宜、确定和可审计；
- 每个错误能被归因到接口、状态、Skill、模型、机制或理论，而不是笼统归因为“插件不工作”。

最终原则：

> **程序提供可达能力，Skill 提供词关系与认识边界，主对话 AI 根据完整语境决定是否以及如何使用能力。**
