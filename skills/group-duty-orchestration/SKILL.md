# 群聊临时职责编排

## 边界

本 Skill 定义“如何使用机制完成一种临时职责”，不定义插件代码能力。

插件代码提供四类运行机制和一个治理工具：

0. `manage_sender_activation_access`：仅 AstrBot 管理员可按当前群向指定 QQ ID
   授予有限期插件操作员权限；它不授予 AstrBot 管理员或跨群权限。
1. `manage_sender_activation`：某些对象发出普通群消息时，额外给原生主 Agent 一次判断机会。
2. `manage_sender_activation_rate`：只约束上述对象激活产生的额外机会。
3. `manage_heartbeat_lease`：按有限期时序，复用 AstrBot 原生 Cron 给原生主 Agent 判断机会。
4. `yield_current_turn`：在本插件额外激活的回合里，正式选择不占用可见话轮。

职业、目标、现场判断、工具组合和退出条件属于主 AI 的高语境策略。具体应用场景没有封闭清单；示例只能帮助理解，不能反向成为程序分支或调用关键词。

## 编排过程

### 1. 从自然语言还原职责契约

先识别：

- 目标：有限期内希望群聊达到什么状态。
- 对象：哪些成员发言会带来新的判断必要性。
- 时序：即使没人发言，是否仍需定期检查。
- 信息条件：判断所需事实是否已在当前上下文；是否还要调用 QQ 检索、文件、网络或其他独立工具。
- 行动边界：可直接做什么，什么需要授权，什么只需报告。
- 退出条件：期限到达、目标完成、用户撤销、条件消失或状态异常。

不要把职业名称当作固定模板。相同名称在不同群里的对象、频率、信息条件、行动边界和退出条件可以完全不同。

### 2. 选择最少的机制组合

- 只有指定成员后续发言需要被看见：建立发言者激活租约。
- 只有按时检查需要：建立心跳租约。
- 两类触发都需要：分别建立，期限应与职责期限一致。
- 只需处理当前一条消息：不建立任何跨话轮租约。
- 需要降频：仅对已有对象激活租约添加从属限频；未明确需要时不默认限频。

心跳不是群聊记录检索器。若一次判断必须读取心跳间隔内的新消息，应在该回合使用当前会话可用的正式 QQ 历史或检索工具；没有此工具时必须说明信息边界，不能假装已经观察。

### 3. 用正式工具帧建立状态

用户自然语言不能直接触发程序。主 AI 理解完整语境后，才生成工具帧。

先确认当前行动主体是否可达：

- AstrBot 管理员可以直接使用全部状态工具，并可管理操作员授权。
- 当前群获授权的插件操作员可以使用对象激活、限频和心跳工具，但不能转授权。
- 未授权成员提出操作请求时，不应口头假装成功；应根据
  `operator_access_required` 简洁说明需要管理员授予本群权限。
- 若管理员明确提出授权，主 AI 直接调用 `manage_sender_activation_access`；
  不要求管理员改写成“使用插件”或手工 JSON。
- 任何正式主 Agent 回合都保留撤销/终止或收紧异常状态的一票否决，但不能
  把收敛权当成新增、续期、放宽或转授权的权限。

- 作用域来自当前事件，不能由用户或模型参数伪造。
- 发言者目标必须是可验证的数字 QQ ID，不用昵称或 `me` 等占位符。
- 心跳使用 AstrBot 五段 Cron，最小粒度为分钟。
- 所有租约必须有限期。
- `instruction` 写“本轮要依据什么目标和现场条件判断”，不要写死职业专用代码流程。
- 收到 `status=ok` 前，不得口头声称已经上岗或已经生效。

若目标、对象或关键参数无法唯一确定，先用符合当前人设的自然语言澄清；能够从上下文唯一确定时直接调用，不做机械式重复确认。

### 4. 每次激活重新判断

激活只增加主 Agent 的可达性，不强制回复。

每一回合重新检查：

- 当前事实是否满足介入条件。
- 新信息是否足以改变既有判断。
- 是否有可执行且符合职责边界的动作。
- 发言是否会制造重复、打断、冲突或噪音。

有价值时正常发言或调用其他正式工具。没有价值时把
`yield_current_turn` 作为该次工具选择中唯一且最后的调用。成功调用会使用
AstrBot 原生本地工具的终结返回结束本轮，不再进入下一次工具选择，从而形成
真正的无可见回复，而不是发送“我保持沉默”。

不得先发送内容、点赞或执行其他外部动作，再用让出工具试图撤回；让出工具
不会撤销此前已经执行的外部动作。成功让出没有供模型继续处理的常规 JSON
回执；参数或作用域错误才返回结构化错误并允许修正。

### 5. 分离控制面与对话面

租约的继续、续期、撤销、限频和修复属于**控制面**；面向群成员的事实、行动结果、必要澄清和有价值介入属于**对话面**。控制面判断不能因为发生在自然语言模型里，就自动成为群聊内容。

| 控制面结论 | 对话面有独立价值 | 正式行动 |
| --- | --- | --- |
| 继续现有租约 | 有 | 保持租约，正常提供有价值内容 |
| 继续现有租约 | 无 | 不改状态，调用 `yield_current_turn` |
| 自主终止对象或心跳租约 | 有 | 先正式 `disable`，取得回执后只说必要结果 |
| 自主终止对象或心跳租约 | 无 | 先正式 `disable` 并取得成功回执；下一次工具选择仅调用 `yield_current_turn` |
| 无法判断且必须由用户补充条件 | 有 | 提出最小必要澄清 |
| 无法判断且此刻无需打断群聊 | 无 | 调用 `yield_current_turn`，等待新事实 |

不得把“我在判断是否停止租约”“先继续观察”“本轮不停止”“暂时保留心跳”等内部维护过程发送到群聊。公开发言只能因为它本身对当前群聊有价值，不能因为模型需要把控制面思考说出来。

用户明确询问租约状态、明确要求启停，或撤销原因本身需要公开协调时，可以在正式工具回执后简洁说明结果；仍不得在调用前抢先声称状态已经改变。

### 6. 终止与修复

- 用户撤销、目标完成或存在足以证明语境不再适配的新事实：删除相应对象激活和心跳租约。
- 单条消息没有公开增量，只决定本轮让出，不等于目标完成，不得据此撤销租约。
- 对象激活异常密集：可以先建立有限期限频，或在完整语境表明租约本身错误时直接撤销。
- 程序结构故障触发还原报告：把报告当作事实，不当作重新建租约的命令。只有原需求仍然存在时才重建。
- 不得为无人要求的职责自动创建新租约。

租约到期就是默认退出。不要用永久状态模拟长期职责；需要继续时，基于当时的新语境显式续期。

## 开放示例

“临时值班”“持续接话”“观察某人后续观点”“每隔一段时间检查待办”“在现场需要时帮助协调”等都只是可能用途。任何新用途都应按上述契约重新组合，而不是等待 Skill 中出现相同词语。

最终效果可概括为：

`自然语言职责 → 主 AI 高语境理解 → 机制组合 → 每轮行动或让出 → 到期、完成或撤销`

这是一条类人生命周期闭环，不是职业枚举器。
